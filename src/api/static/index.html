Step 1

Capture the traffic

Raw packets are read off the network card and grouped into conversations, called flows. One flow is one machine talking to one port on another machine.

Step 2

Score every conversation

A random forest trained on 2.8 million labelled records judges each flow on its duration, size and packet count. It catches floods and brute force attempts.

Step 3

Watch the bigger picture

Some attacks look ordinary one flow at a time. A second layer counts behaviour across flows, which is the only way a port scan or a beacon becomes visible.

Why two layers. A single connection to a closed port is four numbers: almost no duration, one packet, no data. A single ordinary connection is the same four numbers. No model can separate them, because the difference is not in the connection, it is in the pattern. One machine touching a thousand ports in a minute is an attack. The same machine touching three is a browser.

What that cost. Tested against a real port scan captured on a live machine, the model alone caught 3 connections out of 2,050. The behaviour layer caught the scan outright. Both numbers are in the repository, along with the three train-and-serve mismatches found while chasing the gap.
